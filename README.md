# URL Shortener — сервис сокращения ссылок

Консольный сервис сокращения ссылок на Java (Maven) с лимитом переходов,
ограничением времени жизни ссылок и идентификацией пользователей по UUID.

## Возможности

- **Сокращение ссылок**: длинный URL → короткая ссылка вида `clck.ru/XXXXXXX`.
- **Уникальность для каждого пользователя**: один и тот же URL, сокращённый
  разными пользователями, даёт разные короткие ссылки (код вычисляется
  как SHA-256 от пары «UUID пользователя + URL» в алфавите base62,
  при коллизии добавляется счётчик попытки).
- **Лимит переходов**: пользователь задаёт максимальное число переходов.
  Когда остаётся последний переход, владелец получает предупреждение;
  при исчерпании лимита ссылка блокируется, владелец получает уведомление.
- **Время жизни ссылки (TTL)**: задаётся системой в `.env`-файле
  (по умолчанию — сутки). «Протухшие» ссылки удаляются автоматически
  (фоновая очистка раз в минуту + проверка при каждом обращении к ссылке),
  владелец получает уведомление.
- **Идентификация по UUID**: авторизации нет; UUID генерируется при первом
  создании ссылки. Редактировать и удалять ссылку может только её создатель.
- **Переход по ссылке**: ввод короткой ссылки в консоль открывает исходный
  ресурс в браузере (`Desktop.getDesktop().browse(...)`).
- **Мультипользовательский режим**: у одного пользователя может быть сколько
  угодно независимых ссылок; пользователи изолированы друг от друга.

## Требования и зависимости

- **Java 17+** и **Maven 3.6+** — единственное, что нужно установить вручную.
- Внешние библиотеки: только **JUnit 5** (scope `test`) и плагины Maven
  (surefire, checkstyle) — подтягиваются автоматически из Maven Central
  при первой сборке (`mvn package`), отдельная установка не требуется.

## Сборка и запуск

```bash
mvn package          # сборка (тесты выполняются автоматически)
mvn test             # только тесты
mvn checkstyle:check # линт
java -cp target/classes com.example.urlshortener.ConsoleApp   # запуск
```

## Как пользоваться

| Команда | Описание |
|---|---|
| `create <URL> [лимит]` | сократить ссылку (UUID создаётся при первом вызове) |
| `open <ссылка\|код>` | перейти по короткой ссылке (откроется браузер) |
| `login <UUID>` | войти под своим UUID |
| `list` | мои ссылки |
| `limit <код> <число>` | изменить лимит переходов (только владелец) |
| `delete <код>` | удалить ссылку (только владелец) |
| `help` | справка по командам |
| `exit` | выход |

Совет: можно просто вставить короткую ссылку в консоль — выполнится переход.

### Пример сессии

```
> create https://www.baeldung.com/java-9-http-client 2
Создан новый пользователь. Ваш UUID (сохраните его!): 047a338d-...
Короткая ссылка: clck.ru/5ym9amV

> clck.ru/5ym9amV
Открываю https://www.baeldung.com/java-9-http-client ...

> clck.ru/5ym9amV
[Уведомление] Переходы по ссылке clck.ru/5ym9amV закончились: достигнут лимит 2.

> clck.ru/5ym9amV
Ошибка: Лимит переходов по ссылке clck.ru/5ym9amV исчерпан

> limit 5ym9amV 10
Лимит обновлён.
```

## Настройки

Все ключевые параметры читаются из **.env-файла** в корне проекта:

| Переменная | По умолчанию | Описание |
|---|---|---|
| `LINK_TTL_MINUTES` | `1440` (сутки) | время жизни ссылки, задаётся системой |
| `BASE_URL` | `clck.ru` | базовый адрес коротких ссылок |
| `DEFAULT_MAX_CLICKS` | `100` | лимит переходов, если пользователь не задал свой |

Приоритет источников: **переменная окружения > .env-файл > значение по умолчанию**.
Например, `LINK_TTL_MINUTES=60 java -cp target/classes com.example.urlshortener.ConsoleApp`
временно переопределит TTL, не трогая файл. Если `.env` отсутствует или параметр
в нём не задан — применяются значения по умолчанию.

## Архитектура

Слоистая структура: модель → хранилище → сервисы → консольный UI.
Зависимости передаются через конструкторы (DI), уведомления — через интерфейс.

```
com.example.urlshortener
├── ConsoleApp                       — UI-слой: консоль, команды, переходы в браузер,
│                                      фоновая очистка просроченных ссылок
├── config/
│   └── AppConfig                    — загрузка параметров из .env-файла
│                                      (приоритет: env-переменная > .env > default)
├── model/
│   ├── User                         — пользователь, идентификация по UUID
│   └── ShortLink                    — ссылка: код, лимит, счётчик, срок жизни
├── repository/
│   └── LinkRepository               — in-memory хранилище (ConcurrentHashMap),
│                                      выборка по владельцу, удаление просроченных
└── service/
    ├── ShortCodeGenerator           — SHA-256(UUID + URL) → base62-код
    ├── UrlShortenerService          — ядро: создание, переходы, лимиты, TTL,
    │                                  контроль прав владельца; типизированные
    │                                  исключения (NotFound/Expired/ClickLimit/AccessDenied)
    ├── NotificationService          — интерфейс канала уведомлений
    └── ConsoleNotificationService   — консольная реализация уведомлений
```

Ключевые решения:

- **Уникальность без централизованного счётчика**: код — функция от
  (UUID, URL), поэтому разные пользователи детерминированно получают разные
  ссылки на один ресурс; коллизии разрешаются счётчиком попытки.
- **TTL с двойной гарантией**: ленивая проверка при каждом обращении
  (`resolve`, `listUserLinks`) + периодическая фоновая очистка, поэтому
  «протухшая» ссылка недоступна, даже если фоновый поток ещё не отработал.
- **Контроль доступа** на уровне сервиса: `updateMaxClicks`/`deleteLink`
  требуют UUID владельца и бросают `AccessDeniedException` чужаку.

## Тестирование

40 тестов JUnit 5 (unit + интеграционные сценарии), запуск: `mvn test`.

| Класс | Что проверяет |
|---|---|
| `ShortenLinkTest` | сокращение, формат кода, уникальность для разных пользователей, отсутствие коллизий на 500 ссылках, отклонение невалидных URL |
| `ClickLimitTest` | подсчёт переходов, предупреждение о последнем переходе, блокировка при исчерпании лимита, уведомления, лимит по умолчанию, повышение лимита владельцем |
| `LinkTtlTest` | TTL на интервалах 10 мин / 1 час / сутки, автоудаление, выборочная очистка, уведомление об истечении |
| `UserAccessTest` | только владелец редактирует/удаляет, изоляция пользователей, несколько независимых ссылок у одного пользователя |
| `ErrorHandlingTest` | валидация URL (8 невалидных форматов), граничные лимиты, несуществующие ссылки, ввод полной ссылки и голого кода |
| `AppConfigTest` | чтение параметров из .env-файла, значения по умолчанию, приоритет переменных окружения, устойчивость к битому файлу |
| `IntegrationTest` | полный сценарий ТЗ: два пользователя → уникальные ссылки → переходы → блокировка по лимиту → уведомления → истечение TTL → удаление |

## Автоматизация

- **GitHub Actions** (`.github/workflows/ci.yml`): при push и pull request
  выполняются сборка, тесты, линт (Checkstyle) и упаковка JAR.
- **Checkstyle** (`config/checkstyle.xml`) — проверки стиля кода.
- **.editorconfig** — единые отступы и кодировка для всех редакторов.
